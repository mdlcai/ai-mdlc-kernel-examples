Build dossier · MDLC kernel

STΛRSHΞILD

A governed security operations console. It correlates signed telemetry into alerts and incidents, proposes response actions that run only after a policy check and human approval (two approvers, neither the proposer, for high-impact actions), and records every change in a hash-chained evidence ledger. This page records what the build produced, what each gate sent back, and what is still open.

Built · v0.1.2 · local deploy

The interactive demo is read-only and runs entirely in your browser on recorded, simulated data. It renders the build's real screens, but it does not connect to a running STΛRSHΞILD, and nothing you do in it is saved. The results on this page come from the real build: its tests, gates and reports.

Open items

  • Load targets in the spec were not met on the single shared build machine (residual R1, ADR-065). Single requests are within target; three load fixes went in before the final redeploy.
  • Command Center performance is marginal: clean Lighthouse runs average 86.5, but the median counted 80 against a bar of 85 (ADR-059, ADR-061). The landing page's last measurement hit a browser error rather than a score (ADR-070).
  • No rate limit at the edge; limits are enforced in the API only.
  • The evidence ledger is tamper-evident inside the database but not anchored outside it, so an attacker with database owner rights could rewrite it (SEC-6). The breached-password check fails open if its service is unreachable (ADR-007).
