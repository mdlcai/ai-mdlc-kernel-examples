WorkGrid

A multi-tenant work-management app that keeps tickets, tasks and projects on one grid. Tickets route by severity and SLA, tasks can depend on each other, workflows can require approvals, and dashboards update in real time. Security audit and smoke fixes: what was found

Findings from the security audit and the smoke runs. Remediated items were fixed in the build. Deferred and accepted items carry the reason recorded in the build.

IDSeverityFindingDisposition
#1HighNo check at boot that production JWT secrets were set. The compose file fell back to public development secrets while running in production mode.Remediated the API refuses to start in production if the secrets are unset, equal the dev defaults, or equal each other.
#2MediumThe stricter 10-per-minute auth limiter was defined but not applied to login, register or refresh.Remediated applied at the auth controller.
#3MediumBehind the proxy, every request showed the proxy's address, so rate limits and audit IPs were shared.Remediated trust proxy is set so the real client address is used.
#4MediumBreached-password screening (HIBP) is not implemented, although SEC-3 describes it.Deferred needs an architecture decision on outbound calls before it is added.
#5MediumNo column-level encryption of personal data. Log redaction and disk encryption are in place.Deferred needs a key-management decision before regulated personal data is stored.
#6, #7MediumTwo moderate advisories in the postcss package (CSS stringify XSS), pulled in by Next.js build tooling.Accepted build-time only and not in the runtime image (ADR-0013). Re-checked on each Next.js minor.
ADR-0011BugRefresh-token JWTs lacked a unique jti.Fixed found at smoke and fixed at the root cause.
ADR-0012BugThe web client did not unwrap the response envelope, so every organization-scoped screen returned "Organization not found".Fixed found by UI smoke and fixed.

Residual after the audit: 0 critical and 0 high items. The remaining medium items are the two deferred (#4, #5) and the two accepted (#6, #7). The content security policy uses the helmet default in production and was not changed, because a stricter policy had broken Next.js hydration in earlier builds. This is recorded as a residual.

Open items

  • Breached-password screening (#4) needs an architecture decision on the outbound call and its allowlist before it is built.
  • Column-level encryption of personal data (#5) needs a key-management decision before regulated personal data is stored.
  • The postcss advisories (#6, #7) are accepted for now. Re-check on the next Next.js minor version.
  • The content security policy in production is the helmet default. A nonce-based policy was not added.
  • Live email and the GitHub and Slack integrations are not exercised. The adapters are no-ops until credentials are configured. No cloud deployment has been made.
  • The load test named in SPEC section 9 has no recorded result in the build reports.
