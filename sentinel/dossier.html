Sentinel

Sentinel is a unified application security scanner. You point it at a repository, domain or IP, and it runs open-source scanners (static code, dependency, web, secrets and infrastructure checks) inside sandboxed containers. It then merges the results into one deduplicated, severity-sorted list with triage and status tracking. This page records what the build produced, which gates passed, what was fixed on the way, and what is still open.

Open items

  • SEC-12 retention: the 90-day findings and 1-year audit retention is defined, but the scheduled purge job is documented rather than running as a cron job.
  • SEC-13 TLS is terminated at the Caddy proxy, so this control is delegated to infrastructure and carried as a note.
  • Production scanner engines: Trivy, Semgrep, OSV-Scanner, gitleaks, checkov, ZAP, Nuclei, nmap and masscan are adapters behind a flag. The remaining adapters and Docker images are logged as technical debt (ADR-006).
  • Spikes still open: gVisor compatibility for raw-socket scanners, ZAP and nmap adapter fidelity, and the egress-firewall implementation (ADR-002, ARCHITECTURE section 8). None block the small-tier build.
  • Deferred low-severity items: Redis without authentication (internal network only), root vendor containers, no email verification (no outbound mail in v1), and per-batch retry cost.
  • Geo signal has_geo is not built (ADR-008). Revisit if a geo-aware feature is specified.
  • Manual checks not recorded as run: the UI walkthrough and the non-authored-input checks in SMOKE-TEST.md.
