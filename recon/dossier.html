Recon

Recon watches the hosts, ports, services and certificates that an organization exposes to the internet. It keeps a baseline for each asset, scans on a schedule, and raises a change event when the exposed surface moves. Each team is a separate tenant, and an asset can only be scanned after its owner proves control of it. Alerts go to Slack, a signed webhook or email, and reports export as PDF, JSON or CSV. This page records what the build produced, what passed, what was fixed on the way, and what is still open.

Result after pass 3: 0 critical, 0 high, and both residual medium items accepted with rationale. Adversarial review confirmed tenant isolation (runtime smoke flow W7), the SSRF guard, authorization-to-scan, idempotent outbox delivery, webhook signing before send, and append-only audit logging.

Open items

  • Production secrets: set VAULT_ADDR and VAULT_TOKEN. Vault was not provisioned, so SEC-9 runs on the environment fallback locally.
  • Encryption at rest (SEC-12) is delegated to the storage layer. Managed-disk or volume encryption must be documented and enabled for production.
  • The nested postcss 8.4.31 inside Next 15 is accepted. Re-run npm audit on each Next minor bump.
  • Domain verification by DNS TXT or HTTP file was not run. The smoke test completed asset verification with the demo auto-verify (ADR-015), which applies only when private targets are allowed. The scan gate that requires an authorized asset is enforced in every mode.
  • Change detection in the smoke test used the demo drift affordance (ADR-016), which is set only in the demo compose file. Production runs produce only real diffs.
  • Alert routing in the smoke test recorded a failed delivery to a self-signed target. The record is correct for that target, but no alert reached a live endpoint.
  • Cloud paths for Vault, Resend, Sentry and Slack are not verified. Email delivery is not verified because the product has no outbound mail in v1.
  • The rate limiter uses an in-memory store. A Redis-backed store is recommended before running more than one instance (SEC-5).
  • The scan engine is the native Node TCP and TLS engine (ADR-007). The naabu and nmap adapters exist behind the ScanEngine interface but were not used in this build.
