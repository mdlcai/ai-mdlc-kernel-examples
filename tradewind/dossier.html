Tradewind

Tradewind is a milestone-escrow marketplace. A client funds a milestone up front through Stripe Checkout, the money stays held until the client approves the work, and then it is released to the freelancer minus a platform fee (10% by default). Either party can open a dispute, which an admin resolves by refund, release or split. Every money movement is written to an immutable double-entry ledger, and a reconciliation check confirms the closed system nets to zero. This page records what the build produced, what passed, and what is still open.

Open items

  • F-A3 is deferred: two medium findings in the postcss copy bundled with Next.js. Re-run the audit on each Next minor upgrade.
  • SEC-12, at-rest encryption, is delegated to the production volume or RDS (KMS or TDE). The dev stack is unencrypted (ADR-008).
  • SEC-17, TLS, is delegated to the reverse proxy in production (HTTP to HTTPS redirect and HSTS). Local dev runs plaintext under a documented exception.
  • Live Stripe is not exercised. The app ran in stub mode with synthetic ids and locally signed webhooks, and no real Stripe externals were provisioned.
  • The cloud deploy path is documented in QUICKSTART but has not been run.
  • Four invariants (INV-7, INV-8, INV-11 and INV-12) are verified by manual documentation rather than a machine check.
