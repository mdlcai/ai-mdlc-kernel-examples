Where the build stands

Version 0.5.2, verified at commit b8b0f99 and recorded as shipped on 12 November 2026. Security domain, comprehensive depth, with controls mapped to HIPAA, PCI DSS, SOC 2 and ISO 27001 (a mapping, not a certification). A Next.js 16 console, an Express 5 REST API, a gRPC trust-core over mTLS that holds the keys, a BullMQ worker and an isolated egress prober, on PostgreSQL (primary and replica) and Redis, behind Caddy in Docker Compose. The local Compose stack is the shipped artifact. Built in an initial pass and three re-entries, with about 30 hours of active build time.

Security audit: what was found

Findings from the audit passes and the reviewer's checks. Remediated items were fixed in the build; deferred items are accepted with the reason recorded.

IDSeverityFindingDisposition
SEC-1MediumAgent workloads could mint long-lived czw_ credentials, skipping the grant TTL, key and purpose scope.Remediated 409 on issue, 401 on use.
SEC-8, SEC-9MediumAn MFA re-auth form without method="post"; a quantum key migration that silently stopped key-scoped policy rules and grants from applying.Remediated migration refuses to move objects off a key that an active rule or grant names (ADR-070).
SEC-18MediumThe readiness-mode gate matched paths case-sensitively, so /api/v1/VAULT/objects reached the vault router.Remediated with a regression test that fails on the old code. A body-parser HIGH dependency advisory in the same pass was fixed by an update.
SEC-28MediumThe internet-facing prober mounted the whole PKI volume, so code execution in it could read the CA key and every service's key.Remediated per-service PKI volumes (0.5.1, ADR-094). Upgrades from 0.5.0 should rotate the internal CA.
SEC-29, SEC-30MediumOne hostile TLS peer could crash the shared prober; slow-drip peers could hold its slots, and one discovery run over 1,000 slow hosts could run for about 7 hours.Remediated absolute handshake deadline, a 20-minute run budget and 2 discovery jobs per worker (0.5.1, 0.5.2).
SEC-2, SEC-4, SEC-13LowAccount existence is enumerable through 409/429 responses; the vault purpose is not bound into the AEAD AAD; server first-paint reads share a per-IP rate bucket.Deferred each needs an API contract or re-seal change with its own ADR.
SEC-31, SEC-32, SEC-33LowProber findings are not bound to the probed host and port; a domain whose DNS fails persistently never lapses; a CT response is buffered up to 10 MB.Deferred reasons in SECURITY-AUDIT.md.

Result at ship: 0 critical, 0 high, 0 medium open; 11 low deferred (SEC-2, 4, 5, 7, 13, 15, 20, 23, 31, 32, 33) plus the compose change-me residual, each with a recorded reason. The post-ship pass 7 findings are not counted in that result and are listed under open items.

Open items

  • Post-ship security pass 7 found 4 high and 1 medium issue in 0.5.2 (SEC-40 to SEC-44). Fixes are written but not committed or verified by the gates. Two more items from that pass are not yet started: the application database role can update and delete audit rows (the hash chain detects this but does not prevent it), and trust-core authorizes RPCs by mTLS peer only, with no per-method check.
  • Lighthouse performance on the landing and dashboard pages sits below 80 and is accepted under ADR-071. The scores move with host load; the fix is performance work, not the acceptance.
  • Leftover test tenants in the dev database keep the worker busy with sweeps, so smoke needed extra worker processes. The job_runs table also grows without a bound.
  • Low security residuals: 11 deferred findings and the compose change-me defaults (loopback only).
  • HSTS is absent on the localhost edge by design under Caddy's local CA (ADR-017), so the WEB-HEADERS compliance row is a residual.
  • Design warnings remain on 16 of 24 screens (cosmetic, 0 fails), including a plans table clipped at 375 px and panels with no capture.
  • Version labels disagree: the console reads 0.1.0 from package.json while VERSION.md says 0.5.2.
  • Registration maps any unique-key conflict, such as a taken tenant slug, to "email already exists", seen as a rare test flake.
  • The CI security job has no .gitleaksignore or Semgrep excludes, so it would fail on its first run on known test fixtures.
