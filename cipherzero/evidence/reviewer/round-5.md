## Focus items

**GD-0058 (C-3, d9793fb): the ops `(tenant_id, id)` index and the two-scope merge — PASS.**
- `pageOf` runs one equality-scoped query per scope (`tenant_id = t [AND job] AND id < cursor ORDER BY id DESC LIMIT take`), served in order by `job_runs (tenant_id, id)` (ops.ts:144-149; schema.prisma:552).
- The merge concatenates both scopes, sorts by id descending (lowercase UUIDv7 text compares the same in JS and in Postgres) and slices to `take` (ops.ts:168). Any row in the overall top `take` is in the top `take` of its own scope, so the merge is exact.
- The new test (ops.test.ts:164-195) pins the two-page walk with ids alternating between tenant and global, with no gap or repeat at the page edge. It also checks that another tenant sees only the global rows.

**GD-0059 (C-4, 802a5bc, changed in a5f40ab): `lastRun` per job — PASS.**
- Ordering: newest `started_at` per scope, `id` as tiebreak, then the newest across scopes. This is correct under the runner's retry semantics (runner.ts:41, :66-74) and the ADR-062 priority, where a manual run starts after a queued cron sweep.
- Efficiency: the `(job, tenant_id, started_at)` index serves each `LIMIT 1` probe by backward scan, and Postgres 17 adds an incremental sort on the tied `id`s. The cost is independent of table size beyond the B-tree depth.
- The regression test (ops.test.ts:128-162) fails on 802a5bc's `windowStart desc` and passes on a5f40ab.
