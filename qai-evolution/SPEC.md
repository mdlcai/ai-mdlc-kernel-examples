## §1 Overview & scope

**Problem.** Quantum circuit development, simulation, validation and release are fragmented and rarely reproducible. Nothing governs which result is trusted.

**Product.** The `qai` Python SDK (circuits, statevector simulation ≤ 20 qubits, Grover, QAOA, validation, benchmarks, governed evolution) and the multi-tenant QAI Platform that runs those workloads as audited jobs. The platform turns their outputs into evidence and gates releases on that evidence. Since Re-Entry R1 it also runs a hybrid pipeline: a classical neural surrogate, then a linear-optics photonic simulation, then gate-model quantum operations, then validation (W8). Since Re-Entry R3 it also runs AI Simulation: it learns a surrogate of a saved circuit from exact simulations, explores the circuit's angles with that surrogate, and confirms the best designs on the exact solver (W9).

**Personas.**
- **Researcher / developer** (`member`): builds circuits and runs simulations, algorithms, validation, benchmarks and evolution.
- **Reviewer** (`member` + reviewer capability): approves release candidates authored by someone else.
- **Tenant admin** (`admin`, `owner`): members, invites, API keys, schedules, the dead-job queue, audit, export.
- **Viewer** (`viewer`, e.g. education): read-only.
- **Integration client** (API key): enterprise systems and agents calling `/api/v1` (W7).

**Non-Goals (V1)** (from RESEARCH.md Pre-Build Review and ADR-05/06/10):
- Real QPU execution and hardware backends.
- The tensor-network backend.
- Simulation above 20 qubits.
- OpenQASM import (export only).
- Email delivery.
- SSO/OIDC.
- Billing.
- Agent-specific connectors beyond the REST API.

**Scope expansion (comprehensive), ADR-11:**
- the operations surface (job queue and dead-letter requeue);
- the audit trail screen;
- data export (evidence, audit);
- the overview analytics dashboard;
- API key management;
- scheduler run visibility.

**Conventions.**
- **Qubit order.** Little-endian: qubit 0 is the least-significant bit of a basis index. The bitstring `"q(n-1)…q0"` is printed with q0 rightmost, as in Qiskit.
- **Numbers.** All amplitudes are complex128.
- **Time.** All times are UTC ISO-8601.
- **Pagination.** List endpoints use cursor pagination (`?cursor=&limit=`, limit 1–100, default 25) and return `{items, nextCursor}`.

**Job params (validated before enqueue, boundary values inclusive):**
- `simulate`: `{shots 0–100000, seed 0–2^32−1 (required), returnStatevector bool (only numQubits ≤ 12)}`. Requires circuitId.
- `grover`: `{numQubits 2–12, marked[] (1–8 distinct ints in [0, 2^n)), iterations? (default optimal ⌊π/4·√(N/M)⌋), shots 1–100000, seed}`.
- `qaoa`: `{graph{numNodes 2–12, edges[[u,v,w?]] 1–66, unique, u≠v}, p 1–5, maxiter 10–500, seed, shots 1–100000}`.
- `benchmark`: `{qubits[] subset of 2–20 (≤ 8 values), depth 1–50, repetitions 1–5, seed}`.
- `validate`: `{seed, shots 1–100000, reference bool}`. Requires circuitId.
- `evolution`: created via `/evolution/runs` only.
- `pipeline`: `{targets[] (1–4 finite numbers in [0, 1]), shots 1–100000, seed, hidden 4–64 (default 16), epochs 100–5000 (default 1000), tolerance 0.001–0.5 (default 0.03)}`. No circuit (circuitId gives 422 UNSUPPORTED). The job's numQubits is `len(targets)`.
- `surrogate`: `{seed (required), parameters[]? (1–6 distinct op indices of parametrised ops; default every parametrised op), samples? 16–4096 (default max(64, 2·3^d) capped at 4096), span 0.01–π (default π), candidates 64–65536 (default 4096), topK 1–10 (default 5), target? (bitstring of length numQubits, highest qubit leftmost; default the most probable outcome at the circuit's own angles), tolerance 1e-6–0.5 (default 0.01)}`. Requires circuitId. Parametrised ops are rx, ry, rz, p, cp and u (3 angles); d is the total number of angles. The circuit must have 1–10 qubits (`circuitId` TOO_MANY_QUBITS) and 1–6 angles (`params.parameters` NO_PARAMETERS or TOO_MANY_PARAMETERS). An index that is not a parametrised op gives `params.parameters[i]` NOT_PARAMETRISED, an index listed twice DUPLICATE (ADR-42); a target of the wrong length or alphabet gives `params.target` INVALID.
- `orb`: `{seed (required), radius 0.01–1 m (default 0.1), conductivity 1e5–1e8 S/m (default 5.8e7, copper), modes 1–20 (default 8), mode 0–(modes−1) (default 0, the lowest), power 1e-3–1e6 W (default 1), pulse 0.5–50 unloaded time constants (default 10), qinRatio 0.01–100 (Q_in / Q0, default 1), qubits 3–8 (default 8; 2^qubits Q_ext settings), budget? 1–2048 oracle queries (default ⌈8·√(2^qubits)⌉), tolerance 1e-9–1e-3 (default 1e-6)}`. No circuit (circuitId gives 422 UNSUPPORTED). The job's numQubits is `qubits`.
- `formula` (Re-Entry R5, ADR-48): `{mode (required: objective | physics | map | state), seed (required), expression (required)}` plus the mode's own keys below. A key outside the mode's list gives `params.<name>` UNKNOWN_FIELD. No circuit, except state mode with `source: circuit`.
  - **expression:** a string of at most 2,000 characters in the `qai.expr` grammar: numbers, the mode's variables, `+ − * / ^` (`**` is accepted for `^`; `^` is right-associative and binds tighter than unary minus, so −x^2 = −(x^2)), parentheses (square brackets `[ ]` group the same way as `( )`, ADR-53), the functions `sin cos tan asin acos atan atan2 sinh cosh tanh exp log ln log10 log2 sqrt abs sign floor ceil min max` (min and max take 2 or more arguments) and the constants `pi` and `e`. Up to 12 definition lines `name = expression` may come before the result line; `#` starts a comment. There is no implicit multiplication. The Greek letters `Ψ` and `ψ` are the name `psi`, and a name may end in the subscript `ₙ`, which is dropped (`Ψₙ` is `psi`, `Eₙ` is `E`), so notation copied from the Evolution Engine reads as written (ADR-51). A name may instead end in the index `[n]` (spaces allowed inside), which is dropped the same way (`Ψ[n]` and `E[n]` are `psi` and `E`); any other index is an error, since there is no indexing (ADR-53). A formula may have at most 512 terms and 32 levels of nesting. A parse error gives `params.expression` INVALID with a message naming the line and column.
  - **objective:** variables `x` (dims 1) or `x, y` (dims 2). `dims` 1–2 (default 1); `xMin` < `xMax` and `yMin` < `yMax`, each in [−1e6, 1e6] (default 0 and 1); `qubits` 3–10 (2-D: 4–10 and even; default 8; 2^qubits grid points, √ per axis in 2-D); `goal` maximize | minimize (default maximize); `budget`? 1–4096 oracle queries (default ⌈8·√(2^qubits)⌉).
  - **physics:** variables `omega q0 qin qext power pulse tau0 g0 gin gext g`. Here pulse and tau0 are in seconds, and g0, gin and gext are γ = ω/2Q for each loss channel, with g = g0 + gin + gext. Keys: `target` extracted | lost | supplied | peakStored | efficiency | extractionFraction (default extracted); `radius`, `conductivity`, `power`, `pulse` (in unloaded time constants) and `qinRatio`, with the orb ranges and defaults; `cavityMode` 0–19 (default 0, the lowest); `points` 2–32 log-spaced Q_ext in [Q0/100, 100·Q0] (default 8); `tolerance` 1e-9–0.5 relative (default 1e-6).
  - **map:** `expression` in `psi, E, n` is Ψₙ₊₁ = f(Ψₙ, Eₙ, n); its result line may begin with the label `Ψₙ₊₁ =`, `ψₙ₊₁ =` or `psiₙ₊₁ =`, or with the current state and an arrow: `Ψₙ →`, `ψₙ →`, `Ψ →`, `ψ →` or `psi →`, where `↦` and `->` are the same arrow (ADR-52). In a label `[n+1]` is the same as `ₙ₊₁`, and `[n]` or a trailing `ₙ` may be added or left out, so `Ψ[n+1] =`, `psi[n+1] =`, `Ψ[n] →` and `psiₙ →` are accepted too (ADR-53). `energy` in `psi, n` (default `psi^2`) gives Eₙ and has the same grammar and limits, with its errors at `params.energy`; its result line may begin with `Eₙ =`, `E =` or `E[n] =`. `psi0` in [−1e6, 1e6] (default 0.5); `steps` 1–1000 (default 100); `bound` 1–1e12 (default 1e6); `tolerance` 1e-15–0.1 (default 1e-9).
  - **state:** `source` amplitudes | circuit (default amplitudes); `shots` 1–100000 (default 4096).
    - amplitudes: the expression is a(k) in `k, N, q` (N = 2^q) and may use the imaginary unit `i` and `re im conj arg`. `qubits` 1–10 (default 3). A circuitId gives `circuitId` UNSUPPORTED.
    - circuit: requires circuitId; the circuit has 1–10 qubits (`circuitId` TOO_MANY_QUBITS) and at least one rotation angle (`circuitId` NO_PARAMETERS). The expression is each angle as a function of `t`, `j` (the angle's index in op order) and `theta` (its stored value). `tMin` < `tMax` in [−1e6, 1e6] (default 0 and π); `points` 2–64 (default 16); `target`? a bitstring of length numQubits, highest qubit leftmost (default the most probable outcome at tMin).
  The job's numQubits is `qubits` (objective and amplitudes), the circuit's (circuit) or 1 (physics and map).
- `protocol` (Re-Entry R6, ADR-49): `{seed (required), nodes 6–10 (default 8), edgeProbability 0.3–0.9 (default 0.5), runs 2–30 (default 30), train 1–4 (default 2), validation 1–4 (default 2), test 1–4 (default 2), candidates 1–8 (default 4), decisionSeeds 1–5 (default 2), evaluationSeeds 2–5 (default 3), epsilon 0–0.1 (default 0.002), shots 64–1024 (default 256), classicalEvaluations 8–1024 (default 64; cut evaluations per test instance and seed for each classical arm, ADR-55), baseline? {p 1–5, maxiter 10–500, initialParams?} (default {p: 1, maxiter: 10}; the §3 evolution config rules and S14 apply, so a score field gives UNKNOWN_FIELD)}`. No circuit (circuitId gives 422 UNSUPPORTED). The job's numQubits is `nodes`. A tenant may hold one queued or running `protocol` job; a second submit, or a requeue of a failed or dead protocol job while another is queued or running, returns 429 QUEUE_FULL with `Retry-After: 60`.
- `requiredKinds` on POST /releases is a non-empty subset of the 11 evidence kinds, `pipeline`, `surrogate`, `orb`, `formula` and `protocol` included.
- `psiRunId` on POST /releases is optional. **Circuit ops schema.** `{gate, targets[int], controls[int]?, params[float]?}`.
- **Gate allow-list:** `h x y z s sdg t tdg sx rx ry rz p u cx cy cz cp swap ccx measure barrier`.
- **Qubits:** indices are in `[0, numQubits)` and distinct within an op.
- **Params:** finite, |θ| ≤ 1e6. The param count must equal the gate arity (rx/ry/rz/p: 1, cp: 1, u: 3).
- **Measure:** `measure` is terminal per qubit; any non-measure op after a measure on the same qubit is rejected.

## §4 Security requirements

**Controls (threat-derived, RESEARCH.md §5.1 and ARCHITECTURE.md §7):**
- **S1 Transport.** HTTPS only through Caddy (`tls internal` locally). `:80` → 308 to `:443`. HSTS only if `HSTS_ENABLED=true`.
- **S2 Sessions.** `__Host-qai_session` (HttpOnly, Secure, SameSite=Lax, Path=/), 12 h idle and 7 d absolute. Rotated on login, tenant switch and role change. Logout deletes the server row.
- **S3 CSRF.** `__Host-qai_csrf` cookie must equal the `X-CSRF-Token` header, and the `Origin` must equal PUBLIC_ORIGIN, on POST/PUT/PATCH/DELETE with session auth. Otherwise 403 CSRF_FAILED.
- **S4 Passwords.** Argon2id; length 12–128; rejected if on the bundled common-password list or equal to the email. Login errors are generic (`INVALID_CREDENTIALS`), and timing is equalised with a dummy hash.
- **S5 Rate limits.** Exceeding any limit returns 429 RATE_LIMITED with `Retry-After`.

  | Scope | Limit | Store failure |
  |---|---|---|

  | Per principal | 600 / min | fail open, in-process fallback |

- **S6 Object-level authz.** Every repository query filters by `tenant_id`, with RLS as the backstop. A foreign id returns 404 NOT_FOUND.
- **S7 RBAC.**

  | Action | viewer | member | admin | owner |

  | Read projects/circuits/jobs/evidence/releases/overview | ✓ | ✓ | ✓ | ✓ |

  API keys carry a role ≤ admin and cannot manage API keys or members.
- **S8 Audit.** Each of these writes an audit event in the same transaction: signup, login success/failure, logout, tenant switch, every create/update/delete above, job submit/cancel/requeue, release evaluate/approve/hold/reject/release, engine promote and rollback, export, API key use (first use per minute), scheduler trigger. Events are append-only, and each tenant's events form a hash chain: the database trigger `audit_events_chain` gives every event the next `seq`, the previous event's hash as `prev_hash`, and `hash` = sha256 over the event's canonical fields and `prev_hash`. `GET /api/v1/audit/verify` recomputes the chain. The chain detects an edited, removed or reordered event; it does not stop a database owner from rewriting the whole chain, and the evidence is hashed, not signed (ADR-54).

## §5 Features & Key Workflows

### Features

**F-1 SDK circuit core.**
- `qai.Circuit(n)` with fluent gate methods, `ops` IR, `to_dict`/`from_dict` (schema per §3) and `to_qasm()` (OpenQASM 2.0 with `qelib1.inc`).
- `qai.compile(circuit, optimize=True)`: validates; decomposes `swap → 3 cx`, `ccx →` the standard 6-cx Clifford+T decomposition, `u →` rz·ry·rz; cancels adjacent self-inverse pairs (h h, x x, cx cx same qubits, …); merges adjacent rotations about the same axis; reports depth and gate counts.
- **AC:**
  - every gate matrix is unitary to 1e-12;
  - compile preserves the statevector (fidelity ≥ 1 − 1e-10) on 200 hypothesis-generated circuits;
  - invalid ops raise `CircuitError` with a field path.

**F-2 SDK statevector simulator.**
- `qai.Statevector.from_circuit(c)` applies each gate via a tensordot over the target axes, starting from |0…0⟩, in little-endian order.

- **AC:**

**F-5 SDK algorithms.**
- `qai.algorithms.grover(n, marked, iterations=None, shots, seed)` uses a phase oracle plus the diffuser.

- **AC:**
  - Grover with n=3 and one marked item succeeds with probability ≥ 0.94 at the optimal iterations;

**F-6 SDK validation & benchmarks.**
- `qai.validation.checks` covers normalisation, unitarity of the compiled circuit (≤ 10 qubits), probability sum, and reproducibility (two runs with the same seed are equal).
- `qai.validation.reference.compare(circuit)` uses Qiskit `Statevector` and gives fidelity up to global phase. It raises `ReferenceUnavailable` if the `[reference]` extra is absent.

- **AC:**
  - the differential suite (≥ 50 circuits, ≤ 12 qubits) has fidelity ≥ 1 − 1e-10;

**F-7 SDK evolution engine.**
- `qai.evolution.evolve(problem, baseline, iterations, epsilon, seeds, rng_seed)` generates candidates by seeded perturbation of the QAOA config (p ± 1 within 1–5, initial angles jittered, maxiter × {1, 1.5}).
- `V(S)`: every seed's run passes the validation checks and the approximation ratio is in [0, 1].
- `J(S)`: mean (1 − approximationRatio) over the seeds.
- Rule: `Decision.ACCEPTED` iff `V(S) ∧ J(S) ≤ J(Ψn) − ε`, otherwise `Decision.REJECTED`. An accepted candidate becomes the checkpoint.
- **AC:**
  - a candidate with V false is never accepted;
  - with ε=1 nothing is accepted;
  - the decision history is deterministic for a fixed rng_seed.

**F-17 SDK hybrid photonic pipeline** (`qai.classical_ai`, `qai.photonics`, `qai.pipeline`; Re-Entry R1, ADR-34).
- `qai.classical_ai.AngleSurrogate(hidden=16, seed=…)`: a 1→H→1 tanh MLP in NumPy. `fit(epochs)` trains it with full-batch Adam on 129 points of the exact inverse map p ↦ 2·asin(√p), using angle-space MSE. `predict(p)` returns RY angles clipped to [0, π]. Training is deterministic for a seed.
- `qai.photonics`: an ideal linear-optics simulator in Fock space.
  - Elements: `BeamSplitter(m1, m2, theta, phi=0)` with matrix [[cos θ, −e^{−iφ} sin θ], [e^{iφ} sin θ, cos θ]], and `PhaseShifter(mode, phi)`. `Interferometer(modes, elements).unitary()` composes them.
  - `permanent(M)` uses Ryser's formula. `transition_amplitudes(interferometer, occupation)` (U = `interferometer.unitary()`) returns ⟨T|U|S⟩ = Perm(U_{T,S})/√(∏s!∏t!) for every output pattern T.
  - Limits: ≤ 8 modes, ≤ 4 photons, ≤ 2,000 elements. Exceeding one raises `CircuitError`.
  - Dual-rail encoding: qubit q is one photon in modes (2q, 2q+1), and |0⟩ is the photon in mode 2q.
  - `from_circuit(circuit)` maps each single-qubit gate exactly (ZYZ) to phase shifters and one beam splitter. `measure` and `barrier` are skipped. Any multi-qubit gate raises `CircuitError` at path `ops[i].gate` with "Linear optics cannot apply a multi-qubit gate deterministically" (KLM, RESEARCH R1).
  - `dual_rail_state(interferometer, num_qubits)` returns the logical amplitudes by bitstring and the post-selection probability. `sample(probabilities, shots, seed)` draws seeded PCG64 counts.

  1. Classical AI: train the surrogate and predict θ_q for each target.

**F-24 SDK Orb Lab** (`qai.orb`; Re-Entry R4, ADR-46). ORB-0 is a falsifiable energy-validation experiment on a spherical cavity with finitely conducting walls, one input port and one extraction port. It is a simplified model: no plasma, no nonlinear media and no FDTD.
- `cavity_modes(radius, conductivity, count)` returns the `count` lowest resonances, ascending in x = ka. TE_l,n has j_l(x) = 0 and TM_l,n has j_l(x) + x·j_l'(x) = 0; f = c·x/(2πa); the degeneracy is 2l+1; δ = √(2/(ωμ0σ)). Q0 is computed by quadrature of the mode fields and returned with its closed form (TE: a/δ; TM: (a/δ)(1 − l(l+1)/x²)), its relative error and the equipartition error |U_E/U_B − 1|.
- `field_map(mode, grid=32)` returns the time-averaged energy density of the mode (m = 0) on the x–z plane, normalised to a maximum of 1, with null outside the sphere.
- `ledger(omega, q0, q_in, q_ext, power, pulse)` integrates coupled-mode theory, da/dt = −(γ0+γ_in+γ_ext)a + √(2γ_in)·s(t) with γ = ω/2Q, over a rectangular pulse and a ring-down of 30 loaded time constants (DOP853, rtol 1e-11). Supplied, extracted and lost energy are integrated as ODE states. It returns ΔE = E_initial + E_supplied − E_extracted − E_lost − E_final as `residual`, and the closed-form extracted energy as `closedForm`.
- `durr_hoyer(objective, budget, rng)` runs Dürr–Høyer maximum finding: Grover search with a moving threshold on the BBHT schedule (λ = 6/5), simulated exactly. Each Grover iteration costs one oracle query and each measured candidate one more. It never exceeds the budget.
- `renyi_divergence(p, q, alpha)` covers α = 0, 1 (KL), ∞ and every other α > 0. It is ∞ off the support of q and raises ValueError on a malformed input.
- `run_orb(*, seed, radius=0.1, conductivity=5.8e7, modes=8, mode=0, power=1.0, pulse=10.0, qin_ratio=1.0, qubits=8, budget=None, tolerance=1e-6)` returns the §3 orb result through six stages:
  1. Model: the mode table, the driven mode and its field map.
  2. Simulate: the ledger for the baseline (Q_ext = Q_in) and for the QAI choice.
  3. Optimize: maximise extracted / incident energy over 2^qubits log-spaced Q_ext in [Q0/100, 100·Q0] by classical exhaustive search, a bounded Brent search on log10 Q_ext, and QAI Dürr–Høyer within the budget.
  4. Validate. Physics checks: `mode_roots` (≤ 1e-10), `q_closed_form` and `equipartition` (≤ 1e-8), `energy_conservation` and `ledger_closed_form` (≤ tolerance), `extraction_bound` (E_ext/E_sup and E_sup/E_inc ≤ 1), `stability` (decay rate > 0, monotone ring-down, U_final/U_peak ≤ 1e-12) and `grover_circuit_agreement` (≤ 1e-10 against `qai.algorithms.grover_circuit` on the state-vector simulator). Comparison checks: `optimum_agreement` (QAI index = classical index) and `continuous_agreement` (within one grid step).
  5. Compare: the information alignment D(h) = D_α(P‖Q_h) for a point-mass P on the optimum, which is −ln Q_h(opt) for every α, minimised over h within the budget; and the success rate against the budget for classical sampling (b/N) and QAI (64 seeded repeats).
  6. Report: `fail` if any physics check fails, else `inconclusive` if a comparison check fails, else `pass`. The reason names the failing checks. When QAI used no fewer queries than 2^qubits, the reason says so.
  Limits are the §3 orb params; out of range → `CircuitError` with the param's name as path.
- `evidence_parts(result, params)` returns `(inputs, outputs, summary)` for the evidence record, without timings or series.
- **AC:**
  - Mode zeros match Abramowitz & Stegun table 10.6 to 1e-6 (TM_1,1 2.743707, TM_2,1 3.870239, TE_1,1 4.493409, TE_2,1 5.763459, TM_1,2 6.116764); Q and equipartition errors are ≤ 1e-8 for the 20 lowest modes.
  - For every Q_ext tested, the ledger residual is ≤ 1e-9 relative and matches the closed form to 1e-9; the long-pulse optimum is the matched coupling 1/(1/Q0 + 1/Q_in) to 0.5 %.

  - `budget=4` is inconclusive (physics passes, `optimum_agreement` fails). A ledger that creates energy fails `energy_conservation`, and the run is `fail`.

**F-27 SDK formula language** (`qai.expr`; Re-Entry R5, ADR-48). A closed math-notation language for user formulas. It is parsed by a recursive-descent parser into a tree of tuples and evaluated with NumPy. No formula text is ever passed to Python's parser, `eval`, `exec` or `compile` (INV-10).
- `parse(source, variables, *, path="expression", complex_mode=False, result_labels=())` returns a `Program` with its definitions, its result, the variables it uses, its term count and `canonical()`, a normalised rendering that is stable under whitespace and `**` vs `^`. The §3 grammar and limits apply: 2,000 characters, 12 definitions, 512 terms and 32 levels of nesting. Nesting is checked before recursing, so no input reaches Python's recursion limit. Errors are `CircuitError(path)` with messages naming the line and column: unknown name (listing the available ones), unknown function, wrong arity, missing operator, unbalanced parentheses, reserved or duplicate definition, and i or the complex functions outside amplitudes. `Ψ`/`ψ` lex as `psi` and a trailing `ₙ` or `[n]` is dropped, with columns still counted in the source; `[ ]` groups like `( )`, and a `[` straight after a name is otherwise an error ("expected an operator before '['"). Labels are compared after `[n+1]` is read as `ₙ₊₁` and a trailing `[n]` or `ₙ` is dropped, on both the source and the declared labels. Each of `result_labels` is a left-hand side and its separator, `=` or `→` (`↦` and `->` are read as `→`). When the last line begins with one of them, the label is skipped; any other `name =` on the last line is still an error, and so is a label with the other separator. `canonical()` renders ASCII (`psi`, no label).
- `evaluate(program, env)` broadcasts over arrays and returns non-finite values instead of raising; callers check them with `first_bad`.
- `packages/qai-sdk/tests/data/expr_vectors.json` holds shared accept and reject vectors (source, variables, canonical form, value or error message). The web's TypeScript mirror must pass them too.
- **AC:**
  - Precedence and associativity: −x^2 = −9 at x = 3, 2^3^2 = 512, 2**−1 = 0.5. Definitions chain. `max(b, 2, 3) − min(x, 0)` evaluates correctly.
  - Every reject vector fails with its message, including `2x`, `foo(x)`, `__import__('os')`, `x.real`, `x[0]`, `1e400`, an unknown variable, 2,000 `(` characters (rejected at column 34, with no RecursionError) and a formula of 600 terms.
  - `Ψₙ₊₁ = cos(Ψₙ) − 0.1*Eₙ` parses in map mode to the canonical form of `cos(psi) - 0.1*E`; the label is rejected without `result_labels`, and `ψ` is an unknown name where `psi` is not declared. `Ψₙ → cos(Ψₙ)`, `psi -> cos(psi)` and `Ψ ↦ cos(Ψ)` parse in map mode to `cos(psi)`, while `Ψₙ₊₁ → cos(Ψₙ)` and `Ψₙ = cos(Ψₙ)` are rejected. `Ψ[n+1] = cos(Ψ[n]) - 0.1*E[n]` and `psi[n+1] = [psi + 1]/2` parse in map mode, while `x[0]` and `Ψ[n] = cos(Ψ)` are rejected (ADR-53).
  - Parsing a 219-term formula takes under 5 ms, and evaluating it over 65,536 points under 200 ms.
  - The module contains no `eval(`, `exec(` or `compile(` (INV-10, lint:invariants).

**F-31 SDK governance gate with evidence completeness** (`qai.evolution`; Re-Entry R6, ADR-49).
- `gate(evaluation, *, expected, j_baseline, epsilon)` returns `(Decision, reason)`. It applies these rules in order:
  1. **Missing evidence.** The evaluation holds fewer or more per-run records than `expected` (instances × seeds), or a record lacks its ratio or its checks. The candidate is `rejected` with "missing evidence: …".
  2. **Invalid output.** V(S) fails on any record: normalisation, probabilitySum, countsSum, historyFinite, ratioInRange or reproducibility. The candidate is `rejected` with "validation failed: …".
  3. **Not better.** J(S) > J(Ψn) − ε. The candidate is `rejected` with "J … is not ≤ J(Ψn) − ε …".
  4. Otherwise the candidate is `accepted`.
- `evaluate_set(instances, config, seeds, shots)` runs QAOA itself for every instance × seed and returns one record per pair. It never takes a supplied score (S14). The first pair is re-run as the reproducibility check.
- `decide` keeps its meaning, and `gate` calls it for rule 3. Evolution runs and the protocol therefore share one acceptance rule.
- **AC:**
  - A complete, valid and better evaluation is accepted.
  - Each of these is rejected with its own reason: one record dropped, one ratio dropped, a NaN probability, counts that sum to shots + 1, and J equal to J(Ψn).
  - The existing evolution tests pass unchanged.

**F-32 SDK evidence protocol** (`qai.protocol`; ADR-49). `run_protocol(params)` validates the §3 protocol params and returns the §3 protocol result. An out-of-range param raises `CircuitError("params.<name>")`. Every random choice derives from `seed` through `numpy.random.SeedSequence(seed).spawn`, so each run has its own independent stream.
- **Instances.** Each run draws G(nodes, edgeProbability) graphs for train, validation and test. Every graph is connected with at least nodes − 1 edges. No canonical graph repeats across the three splits of a run; a repeat is redrawn.
- **Engine per run.** Start from Ψ₀ = `baseline` and propose `candidates` configurations with `qai.evolution.propose`. Score each one on the train instances × the decision seeds and decide it with `gate`. Each accepted candidate becomes the next checkpoint.
- **Selection on validation.** Score every checkpoint on the validation instances × fresh validation seeds and take the best one. It is adopted as Ψ* only if the paired bootstrap 95 % CI of J(Ψ₀) − J(Ψ*) over the (instance, seed) pairs lies entirely above 0. Otherwise Ψ* = Ψ₀.
- **Lock, then test once.**
  - Record the sha256 of Ψ*'s canonical JSON.
  - Then score Ψ₀, Ψ* and each baseline's choice on the test instances × fresh test seeds. The test seeds are disjoint from the decision and validation seeds.
  - A second test evaluation of a run raises an internal error, so the count is 1 by construction.
- **Baselines, same budget.** Each method spends B = candidates + 1 configuration evaluations on the train set, with the same instances, seeds and shots:
  - random search draws B configurations uniformly (p 1–3, maxiter from 10 to 4 × the baseline's, seeded random angles) and keeps the best on train;
  - COBYLA runs SciPy COBYLA over Ψ₀'s 2p initial angles, with p and maxiter fixed and maxfun B.
  Greedy MaxCut (`greedy_maxcut`, one pass) on each test instance is reported as an unbudgeted classical reference.
- **The six tests:**
  - **correctness**
    - Exhaustive enumeration (`exact_maxcut`) gives C* for every test instance.
    - Controls with a known optimum must match: the 8-ring (C* = 8), K₆ (C* = 9) and K₇ (C* = 12).
    - For Ψ*, the expected gap is 1 − ⟨C⟩/C* and the best-sampled gap is 1 − max sampled cut / C*.
    - `consistent` requires every gap in [0, 1], and no sampled or greedy cut above C*.
    - pass iff the controls match and the run is consistent; otherwise fail.
  - **improvement**
    - The paired difference J(Ψ₀) − J(Ψ*) on the test set, one value per run.
    - pass iff its CI lower bound is > 0 and the fresh seeds are disjoint; otherwise inconclusive.
  - **baselines**
    - The test J of each method per run, as a distribution.
    - The paired CI of each method's difference from the evolved method. The verdict is better when the CI is below 0, worse when it is above 0, and indistinguishable otherwise.
    - pass iff every method spent exactly B evaluations. A budget mismatch is fail. Which method wins is reported, not required.
  - **repeatability**
    - pass iff runs = 30, the run seeds are distinct, every value is finite, and re-running run 1 gives an identical record (`deterministic`).
    - runs < 30 is inconclusive. A determinism failure is fail.
    - Each distribution has mean, sd, the quartiles, its CI and a 10-bin histogram.
  - **generalization**
    - pass iff, in every run: the splits are disjoint; the lock was recorded before the test evaluation and matches the evaluated config; and testEvaluations = 1.
    - A violation is fail.
    - The train, validation and test means are reported, with the test CI.
  - **governance**
    - The test uses the first run that adopted a checkpoint, or run 1 against Ψ₀ if none did.
    - Three candidates go through the real `gate` against that run's checkpoint, with ε_g = max(ε, 1e-9), so a candidate that only ties the checkpoint is not accepted (ADR-50):
      - worse: Ψ₀, re-scored on the train set;
      - invalid: the checkpoint's own evaluation, with one probability set to NaN and its counts summing to shots + 1;
      - missing: the checkpoint's own evaluation, with its last record removed.
    - pass iff all three are rejected with the matching reason and the checkpoint's sha256 is unchanged after each one. Anything else is fail.
- **Outcome.**
  - `fail` if any of these fails: correctness, baselines (budget), repeatability (determinism), generalization or governance.
  - Otherwise `inconclusive` if improvement is not pass, or repeatability is not pass because runs < 30.
  - Otherwise `pass`. The reason names the tests.
- The same params give an identical result, timings excluded.
- `evidence_parts(result, params)` returns:
  - inputs: the normalised params;
  - outputs: the status, the budget, and each test's status and headline (the gaps, the improvement CI, each method's test mean and CI, runs, the lock hashes and the injection decisions);
  - summary: the status and tests[{name, status}].
- **AC:**
  - At the defaults with seed 2026, all six tests pass and the improvement CI lower bound is > 0.
  - The controls match. `runs: 5` is inconclusive, with repeatability at "5 of 30 runs".
  - Every injection is rejected and the checkpoint hash is unchanged.
  - A test-only hook that evaluates the test set twice makes the run raise. A test-only hook that drops the lock makes generalization fail.
  - The same params give an identical result and evidence sha256.
  - Out-of-range params, and a score field in `baseline`, give their `params.*` paths.

**F-39 Active Ψ: versioned engine state with promote and rollback** (API).

**F-42 MaxCut scorer and seeded instances** (SDK).

**F-43 Protocol baselines, ablations and corrected statistics** (SDK).
- New param `classicalEvaluations` (§3). Three classical arms run on each run's frozen test instances and test seeds (one draw stream per run, separate from the existing ones), each spending exactly `classicalEvaluations` cut evaluations per instance and seed:

  - local search: steepest 1-flip ascent from a random start, restarting from a new random start at a local optimum;

  - -Q is represented by the classical arms (`ablations` says so).
  - None of them calls the release flow or changes `gate`.

## §7 Error contract

Every non-2xx response is `application/problem+json`:

```json
{ "type": "https://qai.local/errors/validation-failed", "title": "Validation failed", "status": 422,
  "detail": "1 field failed validation", "instance": "/api/v1/projects",
  "code": "VALIDATION_FAILED", "requestId": "01J…",
  "errors": [ { "field": "name", "message": "Name is required", "code": "REQUIRED" } ] }
```

**`code` enum:**
- **4xx:** VALIDATION_FAILED (422), BAD_REQUEST (400), INVALID_CREDENTIALS (401), UNAUTHENTICATED (401), CSRF_FAILED (403), FORBIDDEN (403), SELF_APPROVAL (403), NOT_FOUND (404), NAME_TAKEN (409), VERSION_CONFLICT (409), LAST_OWNER (409), NOT_CANCELLABLE (409), NOT_READY (409), NOT_APPROVED (409), INVALID_STATE (409), HAS_RELEASES (409), TOKEN_INVALID (400), PAYLOAD_TOO_LARGE (413), RATE_LIMITED (429), QUEUE_FULL (429).
- **5xx:** INTERNAL (500), UNAVAILABLE (503).

Rules:
- Field errors use the request JSON path (`params.shots`). Job params list at most 50 field errors; the message counts all of them (ADR-44).
- 5xx carries no internal message or stack trace.
- `requestId` equals the `X-Request-ID` response header (the incoming header is honoured if it matches `^[A-Za-z0-9-]{8,64}$`).
- Cross-tenant ids return 404 NOT_FOUND.
- The web app maps `errors[]` onto fields and shows `title` plus `requestId` in the error banner.

**Recovery behaviour:**
- 401 redirects to `/login?next=`.
- 403 renders the role-required state.
- 409 VERSION_CONFLICT offers reload.
- 429 shows the retry time from `Retry-After`.
- 5xx shows a retry button.
- The job poller backs off 1 s → 5 s.
