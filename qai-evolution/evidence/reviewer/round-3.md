## Findings

None blocking. Low-impact notes:

- **note N-R3-1 (cpu.py):** if the awaiting request task is cancelled, `async with _slots` releases the slot while the worker thread keeps running, so two CPU jobs can briefly overlap. The middleware is pure ASGI with no `wait_for`, and uvicorn does not cancel on client disconnect, so this is not reachable in the current stack.
- **note N-R3-2 (services/ratelimit.py:120-122):** `compile:tenant` is hit before `compile:principal`, so a principal that is already over its 30/min still consumes the tenant's 120/min window. One user or key can therefore starve the tenant's compile budget. This is an intra-tenant fairness issue only. Swapping the order fixes it.
- **note N-R3-3 (routes/api_keys.py:91-96):** count-then-insert is not atomic, so concurrent creates can exceed 25 by a few. A per-tenant advisory lock or a locked row would close it.
- **note N-R3-4 (circuit.py:65-74):** the `_mcache` key relies on `id()`. A direct `ops.pop()` followed by `ops.append(new_op)` can reuse the last op's id and serve a stale measured set. No in-tree code mutates `.ops` directly, and the API path uses `from_dict`.
- **note N-R3-5 (compile.py):** `compile()` does not re-validate a `Circuit(n, ops)` built directly, and merged rotation params can exceed 1e6 in the output. The API always goes through `from_dict`.
- **note N-R3-6 (F-7/F-14):** with ε = 0, an equal J is accepted. The code follows the SPEC rule `J ≤ J_baseline − ε`, but the F-14 acceptance-criteria wording says "strictly decrease". Align the wording.
- **note N-R3-7 (smoke-test.sh):** it is committed as mode 100644. CLAUDE.md's `./smoke-test.sh` will fail with permission denied on a POSIX checkout. `/smoke` uses `bash ./smoke-test.sh`, which works. `git update-index --chmod=+x smoke-test.sh` fixes it.
- **note N-R3-8 (environment):** INV-2 has no FRONTEND-AUDIT.json in this tree (see Re-run here). Run `npm run web:baseline` before ship.
