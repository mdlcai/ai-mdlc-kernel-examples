The commits are cd1bffb and 2360614 (F-21, `qai/surrogate.py`), 18633ba (F-22: `SurrogateParams`, `check_circuit_params`, `services/jobs.py`, the worker runner `surrogate` and migration 0010), bb22a29 (F-23: `/app/surrogate` and `surrogate-panels.tsx`) and 1d4aeff (RB-9). Governance records and `.claude` are excluded.
Verdict: **PASS-ADVISORY.** Tenancy, evidence integrity, the migration and the web surface hold. I found two lows and two infos. One low is a regression from RB-9: it removed the bound on the length of `parameters`. The other low is a worst-case job that is heavier than the commit message claims and still costs 1 unit.

- **Tenancy holds.** Submit runs under `tenant_session`, and its project and circuit lookups are filtered by tenant and backed by RLS. A cross-tenant circuitId returns 404 and a viewer gets 403 (tested). The `Member` dependency is unchanged, and API keys are still capped at admin.
- **Evidence is deterministic and append-only.** The hashed parts contain no `ms`, `msPer*` or `speedup` field. Two identical runs give byte-identical outputs, and the evidence verifies (tested). The 0005 trigger applies table-wide. The 0010 downgrade refuses while any surrogate row exists.
- **Resource bounds hold but are wide.** The heaviest job I could build took **65 s CPU single-threaded**, as the child runs it. That is 54 % of the 120 s wall clock and of RLIMIT_CPU 121. Peak memory was 169 MiB, inside RLIMIT_AS 768 MB. The job costs 1 unit (P6-2).
- **Validation is strict apart from P6-1.** Bools, strings, NaN, huge integers, duplicates, non-parametrised ops, more than 10 qubits, more than 6 angles and a target of the wrong length or alphabet all return a 422 with the SPEC §3 path. However, since RB-9 an over-long `parameters` list of non-integers produces one field error per element: a 256 KiB request gets a **6.8 MB** 422 and takes about **450 ms** of synchronous CPU (P6-1).
- **The web side renders text only.** There is no `dangerouslySetInnerHTML`, `innerHTML`, `eval` or inline `style`. Links use `encodeURIComponent`, and the POST goes through `apiSend`, which sends CSRF with same-origin credentials. Neither `proxy.ts` nor the Caddyfile changed.
- **The SDK uses no pickle, eval, exec, subprocess, file or network calls.** It imports stdlib and numpy only.

The standing advisory still applies: there is no tooling for secret detection or TypeScript SAST.
