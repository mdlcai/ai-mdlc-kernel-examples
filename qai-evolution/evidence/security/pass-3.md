Project: QAI // QUANTUM SDK (ce0ff2f1-2252-49ea-8d2e-5a25f2e08102)
Auditor: fresh-context Security auditor, pass 3
Date: 2026-11-01
Tree audited: HEAD `934ab8f` (remediation commit `7480dec`, ADR-31)
Verdict: **FAIL.** There is one high finding, P3-1: an unauthenticated, unthrottled request blocks an API replica's event loop for about 1 s while the log redactor scrubs the raw request path. It is quadratic regex backtracking. The `_EMAIL` pattern goes back to the F-3 foundation, and RB-2's new `_DSN_CREDS` pattern adds a second trigger. P2-1 is fixed for the event loop: one bounded slot keeps the loop responsive. But the single global slot creates a new cross-tenant starvation path for compile and QASM (P3-2, medium). P2-2 is fixed on the compile and QASM routes. The advisory degradation from passes 1 and 2 still stands: there is no secret-detection or TypeScript SAST tooling.

## Areas re-checked with no new finding

- **`compile:tenant` key.** It uses `str(principal.tenant_id)` from the resolved principal, never client input, so no tenant can charge another tenant's window. The scopes are distinct, so tenant and principal keys cannot collide.
- **503 envelope.** `busy_error()` goes through the standard §7 `ApiError` and adds only `Retry-After: 1`. It discloses nothing about other tenants beyond "busy", which is an inherent signal of a shared slot.
- **Order before the slot.** Authn and the rate limit run first, then `_load` (RLS, foreign id → 404), then the slot. A foreign id never reaches the CPU slot.
- **Key cap scope.** `count_active_api_keys` filters `tenant_id` and `revoked_at IS NULL` inside `tenant_session` (RLS). Revoked keys free a slot, and the test covers this.
- **Test-only changes.** The `test_invites.py` lookup by id is a test fix only.
