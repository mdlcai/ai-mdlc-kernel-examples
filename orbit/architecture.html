Architecture · Orbit 0.3.2

Architecture How a multi-tenant IT command center is put together: one Postgres schema, one API, one web app, and the isolation guarantees that hold them apart.

This is the design as built, not as proposed. Where a decision is load-bearing — the kind that other decisions rest on and that is expensive to reverse — it is called out as such, with the alternative that was rejected and why.

01Problem and scope

IT organisations run tickets, projects, changes, assets, approvals and documentation in disconnected tools. Nothing links the laptop request to the approval, to the asset, to the closing ticket, so ownership, SLAs and audit evidence get reconstructed by hand.

Orbit puts every IT work object in one Postgres schema under one organisation. Each object links to its neighbours, emits an immutable audit event on every mutation, and is pushed live to open browsers.

Persona Role Primary surfaces
Employee requester New request, my tickets, knowledge base, approvals addressed to them
IT technician agent Queue, ticket detail, changes, assets, projects, article authoring
IT manager manager Everything an agent sees, plus approvals inbox, analytics, SLA policies
IT admin admin Everything, plus users, teams, roles, automation rules, audit trail

Scale tier sets the shape

The target is small — under a thousand concurrent users — and that single token decides more of this architecture than any preference did: one Postgres with the framework default pool, no Redis, an in-process scheduler, one instance per service, per-route rate limiting. Every heavier option in section 12 was rejected because this tier does not need it, not because it is worse.

Deliberately not in v1

SSO, OAuth and SAML; file attachments and image uploads; outbound Slack, Teams or PagerDuty webhooks; SMS; mobile apps; billing; internationalisation; offline mode; discovery agents; inbound email-to-ticket; plugins.

02Topology

Load-bearing

Pages and API share one origin. Because https://localhost:8443 serves both, the session cookie is first-party — SameSite=Strict with the __Host- prefix — there is no CORS and no preflight, and the CSP connect-src 'self' already covers the event stream. The alternative, a separate API origin, would force SameSite=None and weaken the cookie posture for nothing.

Every long-running service has a healthcheck and waits on the one beneath it: api on Postgres being healthy and migrate having exited successfully; web and caddy on api being healthy. One Node process per service — api hosts the HTTP server, the event hub and the scheduler loop together. Both Node services run non-root under tini from multi-stage images with a 32 KB header buffer.

03The request path

The middleware order is normative, not incidental. Two positions in it are chokepoints that everything else depends on: the origin guard runs before any handler can mutate, and the entity loader runs before any handler can read a row it was not entitled to.

The rate limiter sits at position 6, ahead of authenticate, which is what lets the login limiter fire before any password is verified — a login flood costs a counter increment, not an Argon2id hash. That ordering is machine-checked as INV-8.

Every non-2xx response leaves through problemHandler as an RFC 9457 application/problem+json envelope with a typed code and field-level errors[]. Nothing writes an ad-hoc error response; INV-6 forbids it. A role that may not use a route gets 404, not 403, so routes cannot be enumerated by probing them.

Conventions that hold everywhere

  • /api/v1 prefix; cursor pagination ?cursor=&limit=, default 25, max 100, responding {data, nextCursor}. Never offset pagination.
  • Optimistic concurrency on every mutable entity: If-Match, missing is 428, stale is 409.
  • Allow-listed ?sort=field:dir and filters. X-Request-Id echoed back.
  • Cache-Control: no-store on all API responses; OpenAPI generated from the zod schemas.

04Tenant isolation

One schema holds every organisation's data, with org_id on every tenant table. That is the cheapest tenancy model to migrate and the easiest to get catastrophically wrong, so the isolation is enforced three times over, at three different levels, and each layer assumes the others may fail.

Load-bearing

The policy fails closed. It reads org_id = NULLIF(current_setting('app.org_id', true), '')::uuid. On a pooled connection whose SET LOCAL has expired, the setting reads back as an empty string; NULLIF turns that into NULL, and org_id = NULL matches nothing. Without the NULLIF the cast would throw, or worse, a naive default would match. The difference between a leak and an empty result is that one function call. 

ALTER TABLE tickets ENABLE ROW LEVEL SECURITY;
ALTER TABLE tickets FORCE ROW LEVEL SECURITY;
CREATE POLICY tickets_org ON tickets
  USING      (org_id = NULLIF(current_setting('app.org_id', true), '')::uuid)
  WITH CHECK (org_id = NULLIF(current_setting('app.org_id', true), '')::uuid);

Eighteen tenant tables carry this. Seven tables sit outside it by design: orgs, users, sessions, password_reset_tokens, org_counters and scheduler_state are system tables, and pending_emails has a nullable org_id because a password reset for an account whose organisation is not yet known belongs to no organisation.

Object-level authorization is a chokepoint, not a sprinkle

Organisation scope stops cross-tenant reads. It does nothing about a requester reading a colleague's ticket in the same organisation. Each module has one load<Entity> middleware that fetches the row inside the scope and applies the ownership rule before the handler runs — a requester sees tickets they raised, approvals addressed to them, assets assigned to them, published articles; an agent and above see everything in the organisation. Every /:id route and every sub-resource route under it — /comments, /timeline — carries the same guard, because sub-resources are where this is usually forgotten. INV-14 fails the build if a new one omits it.

05Data model

Twenty-five tables in eleven groups. Column-level detail lives in the specification.

Group Tables What holds it together
System orgs, users, sessions, password_reset_tokens No RLS — auth module only. Email globally unique; session tokens stored as SHA-256 of the opaque cookie value
People teams, team_members Work routes to a team first and a person second
Ticketing tickets, ticket_comments, sla_policies, ticket_categories Per-org number via a counter row lock; eight SLA columns including paused milliseconds
Approvals approvals Polymorphic subject; a uniqueness constraint prevents two pending approvals for the same pair
Change changes Risk, implementation plan, rollback plan, schedule window, linked ticket
Assets assets, asset_types Tag unique per organisation; assignment history lives in the audit trail, not a column
Projects projects, milestones, tasks Tasks carry a dependency on another task in the same project, cycle-checked in the service
Knowledge kb_articles Generated tsvector with a GIN index over title, body and tags
Automation automation_rules, automation_runs, recurring_tasks Trigger plus conditions and actions as JSONB, evaluated in process
Messaging notifications, pending_emails Transactional outbox; a uniqueness key makes a resend a no-op
Governance audit_events Append-only at the grant level: INSERT and SELECT only, no update or delete policy at all
Load-bearing

The audit trail cannot be rewritten by the application. It is not a convention or a code review rule — orbit_app is granted only INSERT and SELECT on audit_events, and no policy exists for update or delete. Even a full compromise of the API process cannot silently alter history. INV-5 additionally forbids the calls in source, so the mistake fails the lint before it ever reaches the grant.

State machines are data, shared by both sides

Ticket, change, task, approval and project statuses are explicit enums with a transition table in the shared package, queried as canTransition(kind, from, to, role). The service rejects any move not in the table with 409 INVALID_TRANSITION. The web app reads the same table to decide which buttons to offer, so the interface cannot propose a transition the server will refuse.

06Concurrency

Five different races, five different guards. Each one puts the check in the database rather than in application logic, so two processes cannot both believe they won.

Race Guard Losing outcome
Two people editing one record A version column in the UPDATE predicate, required as If-Match 409 VERSION_CONFLICT, with the current version returned
Two tickets claiming one number A counter row updated inside the creating transaction, serialised by its own row lock Serialised; backed by a per-org uniqueness constraint
Two scheduler ticks overlapping pg_try_advisory_lock, plus FOR UPDATE SKIP LOCKED on the sweep Second tick returns immediately; no double escalation
An email sent twice The claim is the guard: a conditional UPDATE marks rows sending before any send Unclaimed rows are invisible to the other worker
Two approval decisions WHERE status = 'pending' in the deciding UPDATE 409 ALREADY_DECIDED

Where several rows must be locked at once — task dependency updates — they are locked in a deterministic order by id, which is the cheapest way to make a deadlock impossible rather than merely unlikely.

07Realtime

Server-sent events, not WebSockets. The traffic is one-directional push; a bidirectional protocol would add an origin-on-upgrade CSRF surface, a message-rate budget and a second authentication path in exchange for nothing this product needs.

  • GET /api/v1/events/stream is authenticated like any other route, and the hub keys clients as Map<orgId, Set<client>> so fan-out cannot cross an organisation.
  • Five concurrent streams per user. The sixth is refused with 429 before a single header is written.
  • A per-organisation ring buffer of the last 500 events serves Last-Event-ID, so a reconnecting browser resumes rather than reloads.
  • An immediate : connected comment forces the proxy to flush headers; a 20-second keepalive holds the connection open. Caddy disables buffering and compression on this path specifically.
  • Publication happens after commit, never inside the transaction, so no client is told about a write that then rolls back.

When the stream fails five times consecutively the browser stops retrying and falls back to polling every 20 seconds. A console that looks live but silently is not is the worst failure mode available here, so the fallback is not optional.

08Background work

No queue, no Redis, no worker container. One loop inside the API process, every 15 seconds, holding a Postgres advisory lock. Each of its four steps is idempotent and safe to skip entirely, which is what makes a single-process scheduler acceptable: a missed tick costs latency, never correctness.

The automation engine runs two shapes of the same question. The event-driven path asks “this happened to one ticket — which rules care?” A scheduled rule is the transpose: “the clock struck — which tickets does this one rule match?” They need separate entry points, and conflating them is how a scheduled rule ends up stamping a timestamp without doing any work.

Sweeps are bounded to 50 rows per tick and yield between steps, because the scheduler shares an event loop with the HTTP server and a long tick would be felt as latency by every open request.

09Frontend

  • Next.js App Router, standalone output. A proxy mints a per-response CSP nonce and sets the full security header set on every HTML response — on both request and response headers, because under strict-dynamic missing one kills hydration.
  • Two route groups. The public group is the landing page and the credential screens; everything else lives behind the authenticated shell and carries robots: noindex.
  • One typed client and a sixty-line hook. useResource fetches and revalidates on the matching server event. No data library: the event stream already does what a cache layer would, and the JS budget is 400 KB.
  • Design tokens are the only source of colour. They live once, in one stylesheet, re-exported to Tailwind. INV-7 forbids a hex literal in any component file, which is what keeps both themes honest.
  • Primitives own the measured contract. Each accessibility rule — the focusable scroll region on a wide table, the 44 pixel target at the phone tier, the error wiring on an input — is implemented once in the primitive rather than remembered on every screen.
Load-bearing

The shared package is the contract. Zod schemas, enums and the transition table live in one place and both sides import them. A field the web app sends is defined in the same file the API validates against, so the two cannot drift into disagreement — and the interface can offer exactly the transitions the server will accept, because it is reading the server's table.

10Threat model

Trust boundaries

  • Internet to Caddy. Only 8443 and the 8080 redirect are exposed. HSTS for two years, TLS 1.2 and above.
  • Caddy to the services. Plain HTTP inside the compose network, unreachable from the host except through Caddy. Forwarding headers are trusted from exactly one hop.
  • Browser to API. Session cookie, CSRF guarded by SameSite=Strict and an origin check, injected script blocked by a nonce-based CSP with strict-dynamic.
Threat Vector Control
Spoofing Credential stuffing, session theft Argon2id at m=19456, t=2, p=1; limiter keyed on address and account, running before the verify; breach-corpus screening by k-anonymity; hashed session tokens rotated on privilege change
Tampering Cross-tenant or cross-user writes, concurrent overwrite Forced RLS plus explicit predicate; the loader chokepoint; version on every write; the transition table
Repudiation “I never approved that” Append-only audit events carrying actor, before and after, and the request id; approvals record decider and timestamp
Information disclosure Sub-resource IDOR, private notes reaching a requester, PII in logs The same guard on every sub-resource; field gating in serialize(); log redaction; no stack traces in the error envelope; cross-organisation reads answer 404
Denial of service Login floods, stream exhaustion, unbounded lists Per-route limiters; five streams per user; a hard page-size ceiling; 256 KB body limit; the scheduler lock
Elevation of privilege Requester changes their own role; an agent approves their own change Role changes are admin-only and audited; approver may not be the requester; the role matrix is tested per endpoint

Residual risks, tracked rather than closed

  • Encryption at rest is delegated to the deployment volume.
  • The event hub is single-instance, with no cross-instance fan-out. Acceptable at this tier, and the first thing to change at the next one.
  • The breach-corpus check fails open when unreachable, and says so in the log. Availability was chosen over strictness, deliberately.

11Invariants

Eighteen rules, machine-checked on every build by a pinned runner against a declarative manifest. The point of writing them down this way is that a claim in a document decays quietly, while a claim in a lint fails loudly. Two are marked manual because no pattern can honestly verify them; those two are evaluated by prose audit at the review gate, which is the only place they carry consequence.

Worth knowing

An invariant is only as good as what it actually matches. INV-8 spent this build ordering two strings, one of which never appeared in the file it searched — it constrained nothing, and passed against a tree with the limiter deliberately removed. It now fails on a login route whose first handler is not the limiter, verified in both directions rather than assumed. INV-11 and INV-12 have the same shape of weakness today: they assert the pinned runners are present, but they are existence checks, so neither would catch a runner that had been edited. A content hash against the kernel reference is the useful amendment.

12Alternatives considered

Every row here was a real fork. The rejected option is usually the better one at a larger scale.

Decision Chosen Rejected, and why
Tenancy Shared schema with forced RLS Schema- or database-per-tenant: migration fan-out and connection count explode for the same isolation guarantee at this scale
Realtime Server-sent events WebSockets add a CSRF surface on upgrade and a second auth path for one-directional push; polling alone misses the visibility goal
Sessions Opaque server-side tokens JWTs cannot be revoked instantly; browser-storage tokens are forbidden outright
ORM Drizzle Prisma's engine complicates the Alpine image and SET LOCAL; Kysely lacks migration tooling; raw SQL loses type inference
Background jobs In-process loop with an advisory lock A queue plus Redis is the right answer one tier up, and unjustifiable overhead at this one
Edge Caddy nginx needs explicit certificate workflow and header-buffer sizing; automatic HTTPS removes both problems
Frontend data A hand-written hook plus event invalidation TanStack Query and SWR are both excellent, and both add a cache layer the event stream already replaces
API topology Browser to a same-origin API A Next.js proxy doubles hops and complicates streaming; a separate origin weakens the cookie
Search Postgres full-text with ranking A search service is another thing to run for a corpus this size
Components Own primitives on Tailwind A stock library carries a recognisable look and hides the accessibility contract rather than stating it once
